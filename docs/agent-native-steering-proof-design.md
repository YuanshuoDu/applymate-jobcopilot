# Native root steering proof

Native root verification rederives consumed same-Turn user steering from the owned `agent_inputs` and root `agent_steps` rows at the proof checkpoint. Fresh verification uses the supplied root Step; recovery uses the latest owned root Step; terminal readback uses the exact candidate Step supplied by the completion path. The checkpoint sequence is compared as PostgreSQL `BIGINT`, and the steering identity binds the source input, accepted sequence, consuming root Step and complete text. It excludes the current Step/cutoff, so a later harmless Step reuses the same proof while a newly consumed steer changes the packet and makes an older report stale.

Steering is appended after the existing Q/A self-attestation evidence and uses the existing private v2 `user_self_attestation` reference family with a distinct `native-user-steering.v1` summary. It is untrusted user context under the immutable goal and criteria, not proof of external facts or actions and not approval, consent, credential or tool authority. No eligible steering leaves the existing packet content unchanged. Incomplete, attachment-bearing or over-budget steering is unavailable rather than clipped or silently omitted. Raw statements, private references and digests must not enter public feedback or events.

The PostgreSQL fixture seeds persisted owner/checkpoint rows and a strict deterministic report; it verifies the database-backed packet/recovery/readback behavior without a live model, authenticated UI or full process-restart claim. The #638 failed-root receipt reader and atomic completion path are not present in this base. After stack integration, that path must call the composite Q/A-plus-steering evidence helper and supply the exact completion Step ID; this Issue does not claim that connection or copy #638 source into this branch.

Native verification request receipts remain persisted in PostgreSQL and the Worker outbox for internal proof correlation. The Web public stream omits the complete `native_verification.*` event namespace while advancing its durable cursor; transcript reconstruction skips these events, and direct transcript projection rejects them. This does not suppress separately projected, sanitized native verification feedback.
